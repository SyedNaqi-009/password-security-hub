2. Password Generation

We strongly recommend a minimum of 16 characters for randomly generated passwords. For passphrases (words), a minimum of 4 random words (or 6+ for higher security) is recommended by industry standards.

Ambiguous characters are letters and numbers that look similar visually, such as 'O' (uppercase letter O) and '0' (number zero), or 'l' (lowercase L) and 'I' (uppercase i). Excluding them makes passwords easier to read and manually type.

No password is 'unbreakable,' but a sufficiently long, completely random password would take current supercomputers trillions of years to guess, rendering it unbreakable for all practical purposes.

3. Password Strength & Entropy

Password entropy is a measure of a password's unpredictability, measured in bits. A higher entropy means the password is harder to guess via brute-force or dictionary attacks. Generally, >80 bits is considered very strong.

Crack time is estimated by calculating the total possible combinations (entropy) and dividing it by an assumed hashing speed (guesses per second). We use conservative estimates reflecting modern, powerful hardware capabilities.

NIST SP 800-63B are digital identity guidelines provided by the National Institute of Standards and Technology. It outlines modern password best practices, such as removing arbitrary expiration rules, avoiding complex composition rules if length is prioritized, and screening against breached passwords.

5. Technical & Algorithms

We use the browser's native Web Crypto API, specifically the crypto.getRandomValues() method. This is a Cryptographically Secure Pseudorandom Number Generator (CSPRNG), which is significantly safer than standard pseudo-random functions like Math.random().

The Web Crypto API provides a built-in, highly vetted, and secure source of randomness directly in the browser environment, eliminating the need to rely on less secure math functions or external servers.

Encryption is a two-way process; data is scrambled but can be reversed (decrypted) with the right key. Hashing is a one-way process; data is turned into a fixed-length string, and it cannot be reversed. Passwords should always be hashed, never just encrypted.
